# KLoCa Lens 메뉴 오류 수정 후보 v1

2026-10-10 · 첨부한 뮤즈 버전 기준

수정본과 코드 검사 22건을 만들었습니다. **대표님의 실제 뮤즈 화면에서 발생한 하얀 화면의 원인 확정 및 수정본의 브라우저 검증은 아직 미완료입니다.**

## 파일

- `muse-version/`: HTTP 서버에서 실행할 수정된 앱.
- `src/navigation-fix.js`: 추가한 React 화면·오류 복구·자료 보존 코드.
- `src/build-fix.cjs`: 첨부본에 수정을 다시 적용하는 빌드 스크립트.
- `src/test-navigation.cjs`: 실제 번들의 함수·컴포넌트·메뉴 액션을 실행하는 검사.
- `qa/test-results.json`: 검사 결과 22/22 PASS. 실제 브라우저 DOM·레이아웃 검사와 구분해야 합니다.
- `DEBUG_REPORT.md`: 확인한 결함, 수정 이유, 검증 범위.
- `MUSE_HANDOFF.md`: 뮤즈나 다음 개발자가 적용·재검증할 절차.

## 실행

압축을 풀고 해당 폴더에서 실행합니다.

```bash
python3 -m http.server 8080 --directory muse-version
```

브라우저에서 `http://localhost:8080/`을 엽니다. HTML을 파일로 직접 열면 모듈 로딩 제한이 생길 수 있습니다.

실제 운영 주소에 적용한 상태는 아닙니다. 별도 Git 브랜치에 보관하며, 기존 다른 버전을 자동 교체하지 않습니다.

## 핵심 변경

1. 스캔 카드·사진·음성·접기 버튼을 React 컴포넌트로 옮겼습니다. 별도 스크립트가 React 화면 안에 요소를 끼워 넣지 않습니다.
2. 대시보드 메뉴는 전용 대시보드 화면을 엽니다. 홈에서는 기존 뮤즈 코드에 적힌 의도대로 영양 대시보드를 제외합니다.
3. 기록·식탁·프로필 형식을 검사합니다. 형식이 잘못된 자료는 계산하거나 임의 수치로 바꾸지 않고 화면에서 제외하며, 수정 전 자료를 기기에 보존합니다.
4. 보기·팝업 오류가 전체 앱을 하얗게 만들지 않도록 오류 복구 화면을 추가했습니다. 헤더와 오른쪽 메뉴는 별도로 남습니다.
5. 번들에 들어 있던 기본 API 키를 제거했습니다. 이미 기기에 저장된 사용자 설정 키는 유지합니다.

## 자료 보존

복구 사본은 기존 키 뒤에 `.recovery.v1`을 붙여 기기의 로컬 저장소에 보관합니다. 기존 앱의 JSON 백업 내보내기에도 포함됩니다. 저장 공간 부족으로 사본을 만들지 못하면 기존 원본 키를 덮어쓰지 않습니다.

백업 JSON에는 기존 프로필 설정이 들어 있으므로, 디버깅 자료를 공유할 때는 API 키 등 개인 설정을 제거해야 합니다.

## 빌드·검사 재현

원본 첨부 ZIP을 `original/`에 풀어 `original/muse-version/`을 확보하고, 이 패키지의 `src`를 같은 상위 폴더에 둡니다.

```bash
node src/build-fix.cjs original/muse-version
node src/test-navigation.cjs
```

제공 환경의 `CODEX_PRIMARY_RUNTIME_NODE_MODULES`가 필요합니다. 스크립트는 그 환경의 Playwright에 포함된 Babel 파서를 사용합니다. 번들 버전이 다르면 적용을 중단하도록 입력 Git blob을 검사합니다. 원본에는 외부 키가 들어 있어 이 패키지와 새 Git 파일에는 포함하지 않았습니다.
