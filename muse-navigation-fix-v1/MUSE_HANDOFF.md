# 뮤즈 / 다음 개발자 인수인계

목표: 기록·대시보드·영양사 클릭 후 하얀 화면이 되는 증상을 실제 브라우저에서 확정·재검증한다.

현재 수정본은 코드 검사 22/22 PASS이고 브라우저 판정은 PARTIAL이다. 대표님 실제 증상의 원인을 확정했다고 보고하지 말 것.

## 먼저 확인

1. 대표님 실제 뮤즈 실행 URL과 이 첨부본의 번들이 같은지 확인한다.
2. DevTools Console에서 기록·대시보드·영양사를 각각 클릭했을 때 첫 앱 오류를 수집한다. 확장 프로그램 오류는 앱 오류와 구분한다.
3. 기기의 식탁·기록·프로필 데이터는 형태만 점검한다. API 키·개인 식사 기록을 로그나 공유 문서에 그대로 넣지 않는다.
4. 현재 원본과 이전 `.bak`에 있는 DOM 삭제 코드를 혼동하지 않는다. 현재 첨부본의 삭제 함수는 비활성화돼 있다.

## 수정 후보 적용

`muse-version/index.html`과 `muse-version/assets/`를 함께 사용한다. 새 번들 이름은 `index-navigation-fix-v1.js`다. 이전 `muse-hero.js`와 헤더 숨김 MutationObserver를 다시 넣지 않는다.

기존 뮤즈 화면을 React 내부로 옮겼다. 기록·식탁·프로필 형식 검사를 추가했고, 제외 자료는 `.recovery.v1` 사본으로 남긴다. 기본 키는 비어 있으며 기기 설정 키는 유지된다. 개발 프로젝트 원본이 있으면 배포 번들 패치에 머무르지 말고 동일 수정을 해당 컴포넌트·자료 로더에 이식한다.

## 브라우저 합격 조건

- 홈 → 기록 → 대시보드 → 영양사 → 닫기 → 식탁 → 홈을 10회 반복하고 앱 예외가 없어야 한다.
- 대시보드 메뉴에서 실제 영양 대시보드가 보이고, 홈에서 스캔 카드가 보인다.
- 스캔 카드·사진 올리기·목록 접기·스캔 카드 접기가 작동하고 홈 복귀 후 중복 요소가 없어야 한다.
- 기록이 없을 때·정상 기록 1건·여러 기록·잘못된 과거 기록 조건을 각각 확인한다. 잘못된 기록은 조용히 사라지지 않고 안내와 원본 복구 사본이 남아야 한다.
- 식탁에 담기 → 수량 수정 → 식사 완료 → 기록 상세에서 항목과 합계가 일치해야 한다.
- 위젯 접기·펼치기·드래그, 모바일 터치, 가로·세로 화면을 확인한다.
- 보기 오류를 강제로 일으켰을 때 헤더·메뉴·복구 버튼이 남아야 한다.
- 기존 사용자 설정 키가 유지되고, 배포 파일에 키가 다시 들어가지 않아야 한다.

실제 AI·결제 요청은 별도 권한·비용 범위를 확인한 다음 필요한 경우만 테스트한다. 흰 화면 검증에 결제나 유료 AI 호출은 필요하지 않다.

기존 운영본 자동 교체와 배포는 이 작업 범위에서 실행하지 않았다. 최종 브라우저 검사 이후 실제 적용 여부를 별도로 결정한다.
